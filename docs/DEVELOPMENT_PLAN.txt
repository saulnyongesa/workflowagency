1. DESIGN DIRECTION
-------------------

We will use an AI job marketplace theme inspired by major AI-work platforms such as Outlier AI and Handshake AI.

Important design rule:

We can learn from their public design patterns, but we should not copy their exact brand assets, logos, illustrations, wording, or proprietary page layouts. The final product should feel modern and trusted while still having its own brand identity.

Theme characteristics:

- Clean, professional, mobile-first job marketplace interface.
- Light main theme with dark/navy accent sections where needed.
- Strong search and filtering for jobs/opportunities.
- Opportunity cards with reward amount, category, difficulty, available slots, status, and action button.
- Trust metrics such as total paid, active workers, open jobs, verified tasks, and payout success.
- Simple onboarding flow: register, activate, complete profile, start earning.
- Dashboard focused on "available jobs", "wallet", "referrals", and "next action".
- Friendly but serious earning experience, avoiding scam-like visuals and exaggerated claims.
- Clear payout, review, and job approval rules.

Visual foundation:

- Colors: white/off-white background, deep navy text, blue/teal accent, green success, amber warning, red danger.
- Typography: clean sans-serif, readable on mobile, no tiny dashboard text.
- Components: cards, tabs, filters, badges, progress indicators, empty states, alerts, tables, drawer/offcanvas navigation.
- Icons: use Bootstrap Icons or lucide-style SVG icons through a consistent icon set.
- Mobile navigation: bottom nav for Dashboard, Jobs, Wallet, Referrals, Profile.
- Desktop navigation: left sidebar or top navigation depending on final UI tests.


2. PERFORMANCE AND PAGESPEED TARGETS
------------------------------------

The site must be planned for strong PageSpeed Insights results from the beginning, especially on mobile.

Target scores:

- PageSpeed/Lighthouse Performance: 90+ on mobile, 95+ on desktop where practical.
- Accessibility: 90+.
- Best Practices: 90+.
- SEO: 90+ for public pages.

Core Web Vitals targets:

- LCP: 2.5 seconds or faster.
- INP: 200 milliseconds or faster.
- CLS: 0.1 or lower.

Pages to test in PageSpeed Insights:

- Landing page.
- Register page.
- Login page.
- User dashboard.
- Jobs list.
- Job detail/submission page.
- Wallet/deposit page.
- Referral page.
- Product store.
- Admin dashboard.

Performance rules:

- Build mobile-first and avoid heavy JavaScript frameworks.
- Use server-rendered Django templates.
- Use Bootstrap selectively; remove unused CSS in production if possible.
- Defer non-critical JavaScript.
- Keep custom JavaScript small and page-specific.
- Use compressed and responsive Cloudinary images.
- Lazy-load below-the-fold images.
- Set width and height on images to prevent layout shifts.
- Use pagination instead of loading huge lists.
- Use database indexes on search, job status, user, wallet, payment, and referral fields.
- Use select_related/prefetch_related to avoid N+1 queries.
- Cache safe dashboard summaries where useful.
- Use WhiteNoise compressed static files on Heroku.
- Minify CSS and JavaScript for production.
- Avoid autoplay video, large hero animations, and decorative heavy backgrounds.
- Keep first screen useful and fast.

18. PHASE 15: PAGESPEED AND CORE WEB VITALS OPTIMIZATION
--------------------------------------------------------

Goal:

Make the system fast enough for mobile users and strong PageSpeed Insights results.

Tasks:

- Run PageSpeed Insights for public pages.
- Run Lighthouse locally during development.
- Optimize LCP:
  - reduce server response time
  - compress images
  - use responsive Cloudinary transformations
  - avoid oversized hero images
  - preload only critical assets
- Optimize INP:
  - keep JavaScript small
  - defer scripts
  - avoid long main-thread tasks
  - split page-specific JS
- Optimize CLS:
  - reserve image dimensions
  - avoid late-loading banners above content
  - avoid layout-shifting alerts
- Optimize Django queries:
  - add indexes
  - paginate lists
  - use select_related and prefetch_related
  - cache repeated dashboard summaries
- Optimize static assets:
  - minify CSS/JS
  - gzip/Brotli via WhiteNoise
  - long cache headers for static assets
- Optimize admin dashboard:
  - load expensive analytics asynchronously
  - precompute finance snapshots

Deliverables:

- PageSpeed report before optimization.
- PageSpeed report after optimization.
- Performance budget document.

Exit criteria:

- Priority pages score 90+ where practical.
- LCP, INP, and CLS are within good thresholds.
- Any remaining performance issue has a documented reason and fix plan.
