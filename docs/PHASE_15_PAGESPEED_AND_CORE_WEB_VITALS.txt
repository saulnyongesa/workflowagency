========================================

Status: Implemented prototype optimization foundation
Date: 2026-06-29


1. GOAL
-------

Phase 15 prepares the site for strong mobile PageSpeed Insights results by keeping the frontend server-rendered, lightweight, paginated, and static-asset friendly.


2. IMPLEMENTED PERFORMANCE WORK
-------------------------------

- Uses Django templates with Bootstrap and vanilla JavaScript instead of a heavy frontend framework.
- JavaScript is deferred.
- Public landing page no longer contains the bulky account overview card.
- Sidebar and filters are handled with small vanilla JS helpers.
- Jobs list is paginated at 25 rows per page.
- Product list is paginated at 24 cards per page.
- Static files use WhiteNoise compressed manifest storage.
- SVG logo assets are lightweight and served from static files.
- Product/job image placeholders avoid broken image layouts.
- Mobile filters collapse by default to keep content visible.
- Admin and user pages use server-side rendering and database query filtering.

5. VERCEL PROTOTYPE NOTES
-------------------------

Vercel can serve Django through its Python runtime and Vercel Functions. It detects `manage.py`, reads the Django WSGI/ASGI entrypoint, runs static collection, and serves static files through the Vercel CDN when `STATIC_ROOT` is configured.

For this repository:

- `pyproject.toml` points Vercel to `config.wsgi:application`.
- `.env.vercel.prototype` lists the required environment variables.
- The client prototype uses bundled `prototype.sqlite3`, copied to `/tmp` at runtime.
- Treat the bundled database as demo data only; use PostgreSQL for persistent staging and Heroku production.
- Use Cloudinary for uploads.
